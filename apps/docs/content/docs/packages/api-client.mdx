```sh
npm install @aperture-browser/api-client effect
```

Each API area is a service: `AuthApi`, `SessionsApi`, `SnapshotsApi`, `TenantsApi`, `UsersApi`, `TokensApi`, `EventsApi` and `HealthApi`. `apiClientLayer` provides all of them over the `HttpClient` your app supplies, and `baseUrlLayer` points it at an instance on another origin. Failures are `ApiRequestError`s carrying the server's error code and HTTP status.

```ts
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as FetchHttpClient from "effect/unstable/http/FetchHttpClient";
import { apiClientLayer, baseUrlLayer, SessionsApi } from "@aperture-browser/api-client";

const credentials = {
  kind: "bearer",
  token: process.env.APERTURE_TOKEN!,
  authorityType: "tenant",
  tenantId: "my-tenant",
  selectedTenantId: null,
} as const;

const program = SessionsApi.use((sessions) => sessions.listSessions(credentials, { limit: 20 }));

const layer = apiClientLayer.pipe(
  Layer.provide(baseUrlLayer("https://aperture.example.com")),
  Layer.provide(FetchHttpClient.layer),
);

const page = await Effect.runPromise(program.pipe(Effect.provide(layer)));
```

### Fixed credentials

A caller that always acts with the same credentials, such as a server holding one API token, can bind them once. `apertureClientLayer(credentials)` provides `ApertureClient`, which groups `sessions`, `snapshots`, `tenants`, `users`, `tokens` and `events` with the same methods minus the credentials argument, plus `auth.getAuthMe()` and `health.getHealth()`. `withCredentials(service, credentials)` binds a single service the same way.

```ts
import { ApertureClient, apertureClientLayer } from "@aperture-browser/api-client";

const layer = apertureClientLayer(credentials).pipe(
  Layer.provide(baseUrlLayer("https://aperture.example.com")),
  Layer.provide(FetchHttpClient.layer),
);

const program = Effect.gen(function* () {
  const client = yield* ApertureClient;
  const base = yield* client.snapshots.getSnapshotByName("signed-in-base");
  const { session } = yield* client.sessions.createSession({
    baseSnapshotName: Option.isSome(base) ? base.value.name : null,
    browser: { channel: "chromium" },
    proxy: {
      upstreams: { office: { url: "socks5://proxy.example.com" } },
      rules: [{ match: "*", via: "office" }],
    },
  });
  yield* client.sessions.updateSessionProxy(session.id, { rules: [] });
});
```

### Pagination

Every paginated list (sessions, snapshots, tenants, users, admin and tenant tokens, events, audit events) has the same three calls, derived from one generic: `listX(params)` fetches one page (pass the previous `meta.nextCursor` as `cursor`), `streamX(filter)` is a `Stream` of items that fetches the next page only when pulled, and `listAllX(filter)` collects every page. The filter is the list params without `cursor`; its `limit` is the page size.

```ts
const page = yield * client.sessions.listSessions({ status: "running", limit: 20 });
const all = yield * client.sessions.listAllSessions({ status: "running", limit: 100 });
```

`getSnapshotByName(name)` returns an `Option`, since the API has no direct lookup by name.

### Session files

`listSessionFiles(sessionId)` lists a session's files, and `sessionFileTree(files)` arranges them into directory and file nodes for a tree view. The top-level `downloads`, `recordings`, `uploads` and `outputs` always appear. `uploadSessionFiles(sessionId, files, { directory })`, `deleteSessionFile(sessionId, relativePath)` and `moveSessionFile(sessionId, { from, to })` manage files in any retained state; moves never overwrite. `createSessionFileDownloadURL(sessionId, { relativePath, disposition: "inline" })` returns a signed URL usable as an `<img>` source. Upload contents may be a `Blob`, a `Uint8Array` or a byte `Stream`. Any stream makes the whole request body streamed, which browsers other than Chromium cannot send. Each file carries `relativePath` for `browser_file_upload` and `sandboxPath` for CDP `DOM.setFileInputFiles`.

```ts
const program = Effect.gen(function* () {
  const client = yield* ApertureClient;
  const tree = sessionFileTree(yield* client.sessions.listSessionFiles(sessionId));
  yield* client.sessions.uploadSessionFiles(sessionId, [{ name: file.name, content: file }]);
  yield* client.sessions.moveSessionFile(sessionId, {
    from: "downloads/report.pdf",
    to: "uploads/report.pdf",
  });
  const preview = yield* client.sessions.createSessionFileDownloadURL(sessionId, {
    relativePath: "outputs/page.png",
    disposition: "inline",
  });
  return { tree, previewUrl: preview.url };
});
```

### The live session

The live-session calls reach the running session directly and take an optional `sessionToken` in place of the credentials: `uploadLiveSessionFiles` stores files in its `uploads` directory, `setSessionViewport` resizes a target, and `streamSessionRecording` streams a recording as a `Stream` of bytes without buffering it; `downloadSessionRecording` still returns a `Blob`. A failure inside the running session is an `ApiRequestError` with code `live_session_error`, its HTTP status, and the session's message.

### Passkeys

Browser passkey sign-in and registration live in `@aperture-browser/api-client/passkeys`, so the main entry does not pull in `@simplewebauthn/browser`. It is an optional peer dependency; install it alongside when you use that entry. `loginWithPasskey()` and `registerPasskey(name)` run the whole WebAuthn ceremony and fail with `PasskeyCeremonyError` when the browser does not complete it. Its `reason` is `cancelled` for a dismissed or timed-out prompt and `failed` otherwise.

The endpoints, their parameters and error codes are in the [REST API reference](/api-reference).

## api-schema

`@aperture-browser/api-schema` holds the Effect Schemas and a typed `HttpClient` generated from the OpenAPI spec with `@effect/openapi-generator`. `api-client` builds on it; depend on it directly only when you need the raw generated client.

Both require `effect` 4.
